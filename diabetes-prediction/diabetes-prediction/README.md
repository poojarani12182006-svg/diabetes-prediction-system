# GlucoSense — Diabetes Prediction System

An end-to-end Machine Learning web application that predicts the likelihood
of diabetes from eight clinical measurements. Built with **Python, scikit-learn,
Flask**, and a responsive custom frontend — designed as a college AIML project,
but structured like a real production app.

> ⚠️ **Disclaimer:** This is an educational project. Predictions are generated
> by a statistical model trained on a small, limited-population dataset. They
> are **not** a medical diagnosis. Always consult a qualified healthcare
> professional.

---

## 1. Project overview

| Layer | Technology |
|---|---|
| ML / Data | Python, Pandas, NumPy, Scikit-learn, Matplotlib |
| Model persistence | Joblib |
| Backend | Flask |
| Frontend | HTML, CSS, vanilla JavaScript |
| Deployment | Render (or any Gunicorn-compatible host) |

**Pipeline:** raw CSV → clean invalid zero-values → train/test split → scale
features → train Logistic Regression / Decision Tree / Random Forest → pick
the best model by F1-score → save model + scaler with Joblib → serve
predictions through Flask.

## 3. Dataset

This project uses the **Pima Indians Diabetes Dataset** (768 records, 8
features, binary outcome), originally from the National Institute of
Diabetes and Digestive and Kidney Diseases. It's already included at
`dataset/diabetes.csv` with proper column headers:

```
Pregnancies, Glucose, BloodPressure, SkinThickness, Insulin, BMI,
DiabetesPedigreeFunction, Age, Outcome
```

If you ever need a fresh copy, it's also mirrored on several public
repositories (search "pima-indians-diabetes.csv"). Just make sure the column
order matches the header above, or update `FEATURE_COLUMNS` in
`notebooks/train_model.py` accordingly.

## 5. Train the ML model

Run the training script from the project root:

```bash
python notebooks/train_model.py
```

This will:
1. Load `dataset/diabetes.csv`.
2. Replace biologically-invalid zero values (in Glucose, BloodPressure,
   SkinThickness, Insulin, BMI) with `NaN`, then impute them with the column
   median.
3. Split the data 80/20 (stratified) and scale features with `StandardScaler`.
4. Train Logistic Regression, Decision Tree, and Random Forest classifiers.
5. Evaluate each on Accuracy, Precision, Recall, and F1-score.
6. Select the model with the highest F1-score as the "best" model.
7. Save:
   - `model/diabetes_model.joblib` — the trained model
   - `model/scaler.joblib` — the fitted scaler (needed to preprocess future input identically)
   - `model/metrics.json` — metrics for all three models, shown on the website
   - `static/confusion_matrix.png` — confusion matrix for the best model
   - `static/model_comparison.png` — bar chart comparing all models

You should see console output with classification reports and confusion
matrices for all three models.

## 6. Run the website locally

Once the model is trained:

```bash
python app.py
```

By default this starts a development server at **http://127.0.0.1:5000**.

Pages available:
- `/` — Home
- `/about` — About the project & pipeline
- `/predict` — Prediction form (GET to view, POST to submit)
- `/performance` — Model performance metrics & charts
- `/contact` — Contact / project info
- `/api/predict` — JSON API (POST) for programmatic predictions
- `/api/health` — Health check endpoint

### Example API call
```bash
curl -X POST http://127.0.0.1:5000/api/predict \
  -H "Content-Type: application/json" \
  -d '{
        "Pregnancies": 2, "Glucose": 130, "BloodPressure": 78,
        "SkinThickness": 24, "Insulin": 96, "BMI": 31.4,
        "DiabetesPedigreeFunction": 0.42, "Age": 34
      }'
```

## 8. Deploy to the cloud (Render)

1. Push your project to GitHub (see above).
2. Go to [render.com](https://render.com) and sign in.
3. Click **New +** → **Web Service**.
4. Connect your GitHub repository.
5. Configure the service:
   - **Environment:** Python 3
   - **Build Command:**
     ```
     pip install -r requirements.txt && python notebooks/train_model.py
     ```
   - **Start Command:**
     ```
     gunicorn app:app --bind 0.0.0.0:$PORT
     ```
     (This matches the `Procfile`, which Render also reads automatically.)
6. Click **Create Web Service**. Render will build and deploy automatically.
7. Once the deploy finishes, Render gives you a public URL like:
   ```
   https://diabetes-prediction-xxxx.onrender.com
   ```

### Alternative platforms
The same `Procfile` + `requirements.txt` setup also works on **Heroku**,
**Railway**, and **Fly.io** with minimal changes.

## 10. Model performance (reference)

On the held-out 20% test split, the three models scored approximately:

| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| Logistic Regression | ~0.71 | ~0.60 | ~0.50 | ~0.55 |
| **Decision Tree** | **~0.76** | **~0.64** | **~0.72** | **~0.68** |
| Random Forest | ~0.73 | ~0.65 | ~0.52 | ~0.58 |

The Decision Tree was automatically selected as the deployed model (highest
F1-score) at the time this README was written. Exact numbers may shift
slightly depending on library versions — re-run `train_model.py` to see your
own results, which are also displayed live on the **Model Performance** page.

## 11. Notes for extending the project

- Swap in a different dataset by replacing `dataset/diabetes.csv` and
  updating `FEATURE_COLUMNS` in `notebooks/train_model.py` + the form fields
  in `templates/predict.html` and `app.py`.
- Add more models (e.g. SVM, XGBoost) by adding them to the `models` dict in
  `notebooks/train_model.py` — the comparison/selection logic handles any
  number of models automatically.
- Add authentication, a prediction history log, or a database if you want to
  turn this into a multi-user product.
